# 曜聖景觀「自然生活精品」視覺重整規格

## 目標與範圍

本次重整延續「曜聖景觀藝誌」的作品先行架構，但修正現行版本的四項問題：手機導覽展開後的空白與異常形狀、Hero 上方過量留白與粗糙裁圖、按鈕換行與缺乏品牌性、服務／流程／案例卡使用 01–05 卻沒有資訊意義，以及全站中文字過細、近似新細明體。

本次只調整靜態形象網站的視覺系統與前端互動，不新增表單、後端、外部服務或正式圖片生成。聯絡方式維持 LINE、電話與 Email 直接聯絡。

## 品牌方向

採用已確認的 C「自然生活精品」方向：以住宅庭園的親近感為主，保留曜聖的專業施工可信度。整體避免大量奶油底、過度圓角、過多裝飾陰影與無意義編號，以「庭園現場筆記」作為唯一主要記憶點。

### 色彩

- `Forest 700 #315743`：主要行動、導覽聯絡列、流程節點。
- `Forest 900 #172019`：深色外框與高對比背景。
- `Paper 100 #F5F5EF`：主要內容畫布。
- `Stone 200 #D5DBD6`：分隔線與次要邊框。
- `Sun 500 #EFAB51`：品牌焦點、葉脈、流程交替節點。
- `Ink 900 #18241D`：主要文字。
- `Ink 500 #607068`：說明文字；不得低於可讀對比。

### 字型與字重

- 主標題：`LXGW WenKai TC`，字重 700；只用於 Hero、區段主標與案例標題。
- 中文正文與操作文字：`Noto Sans TC`，正文 500、操作與小標 700。
- 英文標籤與資料：`Manrope`，字重 700，搭配克制的字距。
- 三套字型均使用可商用的開源 WOFF2 檔案並放入網站資產；中文字型只保留網站實際使用的字集，不依賴外部字型服務。
- 禁止以系統新細明體作為主要 fallback；載入失敗時改用 `Microsoft JhengHei, PingFang TC, sans-serif`。

## 全站形狀、陰影與動態

### R 角

- Logo、按鈕、導覽控制：8px。
- 內容面板與資訊卡：10px。
- 案例與 Hero 圖片：12px。
- 葉片造型允許 `12px 2px 12px 2px` 與反向組合。
- 禁止使用 50% 膠囊按鈕，也不使用超過 12px 的大圓角容器。

### 陰影

- 靜態卡片只保留低透明度、低高度陰影。
- Hover／鍵盤焦點時才提高陰影與層次；陰影色使用森林綠灰，不使用純黑厚重陰影。
- 流程踏石可使用雙層陰影，模擬石材前後關係。

### 動態

- 卡片 Hover：上移最多 7px、圖片放大最多 `1.035`、箭頭水平移動最多 5px。
- 手機不依賴 Hover，改用按壓與焦點回饋。
- 手機選單從導覽列下方淡入並向下移動最多 8px。
- 所有動畫使用 250–700ms 的單次轉場，不加入持續漂浮或裝飾性循環。
- `prefers-reduced-motion: reduce` 時取消位移、縮放與 Reveal，只保留必要狀態切換。

## 元件設計

### 1. 手機導覽與 Hero

- 頁面頂端使用完整 68px 導覽列；Hero 與導覽之間固定 12px，不保留大面積空白。
- 導覽列在頁面頂端以 68px 完整顯示，捲動後縮成 56px 的固定版本。
- 手機展開選單覆蓋導覽列下方剩餘畫布，不再使用右側抽屜或左側空白遮罩。
- 展開內容依序為「探索曜聖」標題、四條垂直連結、庭園實景圖、LINE／電話聯絡列；不得出現無內容的空白格。
- Hero 手機圖片使用 4:5、桌機使用寬幅構圖；每張照片以資料設定焦點位置。
- 圖上只放置地區／案型的「庭園現場筆記」與必要標題漸層，不使用漂浮圓點。

### 2. 交錯葉片 CTA

- 「瀏覽庭園作品」與「LINE 諮詢」形成一組相連按鈕。
- 第一顆使用 `12px 2px 12px 2px`，第二顆反向；中間重疊不超過 3px。
- 兩顆按鈕包含單色葉片線條圖示，文字必須 `white-space: nowrap`。
- 觸控高度至少 46px，鍵盤焦點框不可被裁切。

### 3. 服務卡片

- 服務不是順序，移除 01–04。
- 每張卡片包含真實實景圖、工法英文標籤、粗體中文標題、簡短說明與一個具體連結。
- 桌機四欄；平板兩欄；手機改為橫向圖文卡，避免形成過長空白卡片。
- Hover 使用抬升、陰影、圖片輕微放大與箭頭位移；資訊本身不隱藏在 Hover 狀態。

### 4. 合作流程

- 流程確實具有先後關係，因此保留 01–05。
- 編號使用交替葉形圓角的「踏石」節點，由路徑線連接，標題與說明緊鄰節點。
- 桌機五步橫向交錯排列；平板與手機改為垂直路徑，不使用固定高度空白網格。

### 5. 作品案例卡

- 移除案例卡上的裝飾性 01、02、03。
- 改以地區、案型與工法說明案例差異。
- 桌機使用一大一小的非對稱景觀型錄；手機統一 4:5 圖片與單欄內容。
- 標題與說明位於獨立資訊帶；圖片上只保留現場筆記，避免遮住工程細節。
- 每張圖片資料新增焦點位置，避免所有圖片使用預設中心裁切。

## React 與資料結構

- 保留現有純 UI 元件與資料檔分離方式，視覺元件只接收 props，不自行取得資料。
- `ProjectCard` 接收 `project`、`priority` 與顯示模式；移除只用於裝飾的 `index`。
- 專案資料新增可選的 `focalPoint`，格式為 CSS `object-position` 值；沒有設定時使用安全預設值 `50% 50%`。
- 服務資料新增英文工法標籤與對應圖片鍵，仍由 `services.js` 提供。
- 導覽開關與捲動狀態保留在 `SiteHeader`，選單內容本身維持展示元件。
- 不新增全域狀態管理或 API；目前資料流仍為資料模組 → 頁面組合 → 純 UI 元件。

## 錯誤與降級處理

- `BrandImage` 繼續處理破圖 fallback；圖片 fallback 必須保留與原圖相同的比例及最小高度。
- 字型未完成載入前使用指定 sans-serif fallback，避免版面跳動造成按鈕換行。
- LINE、電話與 Email 使用標準連結，不依賴 JavaScript 事件才能啟動；選單控制使用標準按鈕與 ARIA 狀態呈現。
- 圖片不做會改變真實工程內容的 AI 修圖；只使用已確認的原始案例資產與確定性壓縮版本。

## 響應式與無障礙驗收

- 驗證寬度：360、390、768、1024、1440px。
- 所有寬度不得水平溢出；導覽、按鈕與中文標題不得非預期換行或裁切。
- 可操作元素觸控尺寸至少 44×44px，具可見的 `:focus-visible` 狀態。
- 手機選單開啟時鎖定背景捲動；關閉按鈕、選單連結、Escape 與路由切換皆可關閉。
- 色彩對比符合 WCAG AA；裝飾葉片與陰影不可成為唯一狀態提示。
- 圖片具正確替代文字，純裝飾圖示使用 `aria-hidden`。

## 測試與完成條件

- 更新 Vitest／React Testing Library 測試，驗證手機選單開關、Escape、外部點擊、正確連結與路由。
- 驗證服務區不再輸出裝飾性編號；流程仍以有序清單呈現 01–05。
- 驗證案例卡不再依賴 `index`，並正確套用焦點位置。
- 執行 `npm test -- --run`、`npm run lint`、`npm run build`。
- 以瀏覽器檢查首頁、案例列表、案例內頁與錯誤頁；確認無框架錯誤覆蓋、無 console error／warning、無破圖。
- 截取手機收合／展開導覽、手機首頁、桌機首頁、服務流程與案例列表，與已確認視覺稿逐項比較。

## 不在本次範圍

- GitHub Pages 或 Vercel 正式部署。
- 新增報價表單、資料庫或後台。
- AI 生成或重建工程照片內容。
- 社群排程、自動發文與成效分析系統。
